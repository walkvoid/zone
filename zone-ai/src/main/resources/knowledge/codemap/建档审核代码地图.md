## 2. 核心数据流

### 2.1 主要业务流程数据流向

```
建档申请提交
  → 启动流程（CustProccessBusinessHandler）
    → 按 applyType 排他网关分流:
    ├── CUST_BUILD（建档/开户）
    │   → 按 custBuildType 分流:
    │   ├── AGW_BUILD（内管端建档）
    │   │   → 采购人员判断自动节点（CustPurchasingAutoTaskHandler）
    │   │     → [custPurchasingFlag=YES] 采购人员审核（CustPurchasingStaffHandler 自定义审批人）
    │   │     → 风控初审（CustFirstCheckTaskHandler: AGW_CUST_RISK_FIRST_CHECK）
    │   │       ├─ pass → 风控复审（AGW_CUST_RISK_FINAL_CHECK）
    │   │       │   ├─ pass → 审核通过（CustPassAutoTaskHandler）
    │   │       │   ├─ reject → 审核拒绝（CustRejectAutoTaskHandler）
    │   │       │   └─ back → 退回补充资料（CustAuthBackTaskHandler: 内管端）
    │   │       ├─ reject → 审核拒绝
    │   │       └─ back → 退回补充资料（CustAuthBackTaskHandler: 内管端）
    │   └── PC_BUILD（客户端建档）
    │       → 风控初审（CustFirstCheckTaskHandler: PC_CUST_RISK_FIRST_CHECK）
    │         ├─ pass → 风控复审（PC_CUST_RISK_FINAL_CHECK）
    │         │   ├─ pass → 审核通过（CustPassAutoTaskHandler）
    │         │   ├─ reject → 审核拒绝（CustRejectAutoTaskHandler）
    │         │   └─ back → 退回补充资料（CustAuthBackTaskHandler: 客户端）
    │         ├─ reject → 审核拒绝
    │         └─ back → 退回补充资料（CustAuthBackTaskHandler: 客户端）
    │             → 供应商端补充资料（CustAuditSpyApproveClientProvider 获取审批人）
    │               → 重新提交 → 风控初审（循环）
    ├── CUST_ACTIVE_CHANGE（开户变更）
    │   （按 custBuildType 区分 AGW_BUILD / PC_BUILD 子路径）
    └── CUST_CHANGE（企业变更）
        → 变更初审（TASK_CUST_CHANGE_FIRST_CHECK）
          ├─ pass → 变更复审（TASK_CUST_CHANGE_SECOND_CHECK）
          │   ├─ pass → 变更通过
          │   ├─ reject → 变更拒绝
          │   └─ back → 退回发起人（PC/AGW）
          └─ reject → 变更拒绝
```

| 流程启动时初始化了哪些变量 | `CustProccessBusinessHandler.doBusiness()` → 解析 businessData JSON |
| 申请类型如何分流 | 排他网关根据流程变量 `applyType` 分流（CUST_BUILD/CUST_ACTIVE_CHANGE/CUST_CHANGE） |
| 内管/客户端建档如何区分 | 排他网关根据流程变量 `custBuildType` 分流（AGW_BUILD/PC_BUILD） |
| 采购人员审核节点何时激活 | `CustPurchasingAutoTaskHandler` 设置 `custPurchasingFlag`=YES（供应商且首次建档） |
| 采购人员审批人如何确定 | `CustPurchasingStaffHandler.getAssigneeList()` → extData.purchasingPerson 或 ROLE-PLATFORM00601 |
| 初审通过后做了什么 | `CustFirstCheckTaskHandler.notice()` → COMPLETE 事件更新变量和通知状态 |
| 退回客户端后做了什么 | `CustAuthBackTaskHandler.notice()` → 更新状态/短信/站内信/步骤条重置 |
| 审核通过后做了什么 | `CustPassAutoTaskHandler.notice()` → 同步信息/行方准入/招行白名单/影像拷贝/产品开通/短信/站内信 |
| 审核拒绝后做了什么 | `CustRejectAutoTaskHandler.notice()` → 更新状态为BUILD_FAIL/短信/邮件/站内信 |
| 站内信场景码 | 通过: CUST_BUILD_02，拒绝: CUST_BUILD_03，退回: CUST_BUILD_04 |
| 变更流程站内信 | `CustGlobalTaskNoticeHandler.sendNoticeOfCustChange()` |
| OA待办发送 | `CustGlobalTaskNoticeHandler.sendOaTodo()` → 仅采购人员审核节点 |
| 节点 ID 常量定义 | `CustWorkFlowConstant` 接口 |
| 流程定义 JSON | `jinkoscf-common/.dev-standards/knowledge/procdefs/建档审核-V34.json` |
