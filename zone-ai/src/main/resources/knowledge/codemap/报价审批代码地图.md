```
┌─────────────────┐     启动流程      ┌──────────────────┐     RPC      ┌─────────────────────┐
│  前端/内管端/    │ ──────────────→  │  工作流引擎       │ ──────────→ │  CashBiddingFacade  │
│  资金方/核心企业 │                  │  (acflow-wkfl)   │             │  (业务RPC)          │
└─────────────────┘                  └──────────────────┘             └─────────────────────┘
                                            │                                   │
                                     监听器回调                          查询/更新报价状态
                                            │                                   │
                                            ▼                                   ▼
                                   ┌──────────────────┐             ┌─────────────────────┐
                                   │  Listener Handler │             │  ts_cash_bidding     │

                                   └──────────────────┘             └─────────────────────┘
                                            │
                                     站内信/短信/OA待办
                                            │
                                            ▼
                                   ┌──────────────────┐
                                   │  NoticeInfoFacade │
                                   │  JinkoOaClient    │

```

### 2.1 关键数据对象

| 对象 | 说明 |
|------|------|
| `CashBiddingDTO` | 报价主数据DTO（含报价编号、类型、资金方、核心企业、供应商、审批状态等） |
| `TsCashBiddingType` | 报价类型枚举：`FINANCE`(直保/再保)、`PREPAYMENT`(提前结清) |
| `TsBiddingManageType` | 报价管理类型：`PLATFORM`(平台方)、其他(客户端) |

## 3. 工作流执行链路

### 3.1 流程概览

```
启动(CashBiddingStartHandler)
  │
  ▼
自动初始化节点(CashBiddingAutoStartTaskHandler)
  │ 设置 formApproveResult = AGW/FINANCE/CORE/PLATFORM/PREPAYMENT
  │
  ├── AGW路径 ──────────────→ 子流程: financeAuditMultiTrans(直保/再保审核)
  │                                     │
  │                            ┌────────┴────────┐
  │                          通过              拒绝/退回
  │                            │                  │
  │                            ▼                  ▼
  │                     审批通过节点        审批拒绝节点
  │
  ├── FINANCE路径 ──────────→ 子流程: financeAuditMultiTrans(直保/再保审核)
  │
  ├── CORE路径 ─────────────→ 子流程: coreAuditMultiTrans(提前结清审核)
  │
  ├── PREPAYMENT路径 ───────→ 子流程: coreAuditMultiTrans(提前结清审核)
  │
  └── PLATFORM路径 ─────────→ 三级审批
                                │
                          财务总监审批
                          (RushSignTask-platformFirstApproval)
                                │
                             VP审批
                          (RushSignTask-platformSecondApproval)
                                │
                          资金管理部审批
                          (RushSignTask-platformThreeApproval)
                                │
                          ┌─────┴─────┐
                        通过         拒绝/退回
                          │            │
                          ▼            ▼
                    成功处理节点   拒绝处理节点
```

### 3.2 关键节点与监听器

| 节点类型 | 节点ID | 监听器 | 触发时机 |
|----------|--------|--------|----------|
| 流程启动 | - | `CashBiddingStartHandler` | 流程启动时 |
| 全局任务通知 | - | `CashBiddingGlobalTaskNoticeHandler` | 任务创建/完成/结束时 |
| 自动初始化 | `AutoTask-1675317990144` | `CashBiddingAutoStartTaskHandler` | 初始化后决定路由 |
| 审批拒绝/退回 | `AutoTask-1666360937483` | `CashbiddingRejectTaskHandler` | 审批被拒绝或退回 |
| 审批通过 | `AutoTask-1666361080500` | `CashbiddingSucessTaskHandler` | 审批最终通过 |
| 子流程前置 | `AutoTask-1687002016956` / `AutoTask-1687002055662` | `CashBiddingAutoTaskHandler` | 子流程进入前设置pass |
| 任务领取 | 平台审批节点（5个） | `BiddingOATaskClaimBusinessHandler` | OA任务领取/退领 |

### 3.3 监听器详细说明

#### 3.3.1 CashBiddingStartHandler（流程启动扩展器）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/processbusinesshandler/cashbidding/CashBiddingStartHandler.java`

**接口**: `IProcessBusinessHandler`

**核心逻辑**:
1. 通过 `BiddingFetcher` 获取报价数据（区分单条/批量）
2. 批量审批：设置 `batchNo`、`biddingSize`、`biddingType`
3. 单条审批：设置报价编号、各方企业ID/名称、报价类型等流程变量
4. 提前结清类型使用核心企业名称，其他使用资金方名称
5. 返回 `businessId` 和流程变量

**RPC依赖**: `CashBiddingFacade`、`BiddingFetcher`

---

#### 3.3.2 CashBiddingGlobalTaskNoticeHandler（全局任务通知）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/globaltasknoticehandler/cashbidding/CashBiddingGlobalTaskNoticeHandler.java`

**接口**: `IGlobalTaskNoticeHandler`

**核心逻辑**:
1. **任务创建通知(type=1/2)**: 子流程节点(`financeAuditMultiTrans`/`coreAuditMultiTrans`)的自动领取时，发送短信给审批人
2. **自动委派**: 通过 `AutoDelegateHandler` 判断是否需要自动委派，委派成功则分别通知被委托人(待办)和委托人(抄送)
3. **OA待办推送**: 仅对平台审批节点(5个`platApproveNode`)发送OA待办
   - 交易报价：`RushSignTask-firstApproval`、`RushSignTask-secondApproval`
   - 服务费报价：`RushSignTask-platformFirstApproval`、`RushSignTask-platformSecondApproval`、`RushSignTask-platformThreeApproval`
4. 根据单条/批量构建OA待办参数，通过 `JinkoOaClientFacade.sendTodoAsync` 异步推送

**RPC依赖**: `CashBiddingMessageFacade`、`CashBiddingFacade`、`JinkoOaClientFacade`、`AutoDelegateHandler`、`BiddingFetcher`

---

#### 3.3.3 CashBiddingAutoStartTaskHandler（自动初始化路由）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/executionlistenerhandler/cashbidding/CashBiddingAutoStartTaskHandler.java`

**接口**: `IExecutionListenerHandler`

**核心逻辑 — 5条路由决策**:

| 条件 | formApproveResult | 说明 |
|------|-------------------|------|
| `TsBiddingManageType.PLATFORM` | `"PLATFORM"` | 平台方报价 → 内管三级审批 |
| 非平台 + 客户端审批关闭 + PREPAYMENT | `"CORE"` | 提前结清 → 核心企业审核子流程 |
| 非平台 + 客户端审批关闭 + 非PREPAYMENT | `"FINANCE"` | 直保/再保 → 资金方审核子流程 |
| 非平台 + 客户端审批开启 + 非PREPAYMENT | `"AGW"` | 内管端 → 资金方审核子流程 |
| 非平台 + 客户端审批开启 + PREPAYMENT | `"PREPAYMENT"` | 内管端 → 提前结清审核子流程 |

**RPC依赖**: `CashBiddingFacade.getConfigFlag()`、`BiddingFetcher`

---

#### 3.3.4 CashbiddingRejectTaskHandler（拒绝/退回处理）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/executionlistenerhandler/cashbidding/CashbiddingRejectTaskHandler.java`

**接口**: `IExecutionListenerHandler`

**核心逻辑**:
1. 仅处理 `START` 事件
2. 根据 `formApproveResult` 区分拒绝(`CHECK_FAIL`)和退回(`RE_CHECK`)
3. 批量更新报价审批状态（通过 `CashBiddingFacade.updateStatusAfterApproval`）
4. 按发起渠道（AGW/资金方/核心企业）发送不同模板的站内信通知
   - AGW端：`CASHBIDDING_04`
   - 核心企业端（提前结清）：`CASHBIDDING_07`
   - 资金方端：`CASHBIDDING_09`
5. 退回时额外发送晶彩通知（钉钉消息）给流程发起人

**RPC依赖**: `CashBiddingFacade`、`NoticeInfoFacade`、`UserInfoFacade`、`JinkoClientProvider`、`BiddingFetcher`

---

#### 3.3.5 CashbiddingSucessTaskHandler（通过处理）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/executionlistenerhandler/cashbidding/CashbiddingSucessTaskHandler.java`

**接口**: `IExecutionListenerHandler`

**核心逻辑**:
1. 仅处理 `START` 事件
2. 将报价状态更新为 `CHECK_PASS`，记录审批人和审批时间
3. 按发起渠道发送通过通知站内信
   - AGW端：`CASHBIDDING_03`
   - 核心企业端：`CASHBIDDING_06`
   - 资金方端：`CASHBIDDING_08`

**RPC依赖**: `CashBiddingFacade`、`NoticeInfoFacade`、`UserInfoFacade`、`BiddingFetcher`

---

#### 3.3.6 CashBiddingAutoTaskHandler（子流程前置自动节点）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/executionlistenerhandler/cashbidding/CashBiddingAutoTaskHandler.java`

**接口**: `IExecutionListenerHandler`

**核心逻辑**: 仅处理 `END` 事件，为子流程(`financeAuditMultiTrans`/`coreAuditMultiTrans`)前置节点设置 `formApproveResult=pass`

---

#### 3.3.7 BiddingOATaskClaimBusinessHandler（OA任务领取）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/taskclaimbusinesshandler/bidding/BiddingOATaskClaimBusinessHandler.java`

**接口**: `ITaskClaimBusinessHandler`

**核心逻辑**:
- 任务领取(`claim`)时通过 `JinkoOaClientFacade.onTaskClaim` 同步OA待办状态
- 监听5个平台审批人工节点的领取/退领事件

## 6. 快速定位指南

| 场景 | 定位文件 |
|------|----------|
| 流程启动失败 | `CashBiddingStartHandler.doBusiness()` → 检查 `BiddingFetcher.fetchBidding()` 返回值 |
| 审批路由错误 | `CashBiddingAutoStartTaskHandler.notice()` → 检查 `BiddingManageType` 和 `BiddingType` 判断逻辑 |
| 审批通过后状态未更新 | `CashbiddingSucessTaskHandler.handleSingle()` → 检查 `CashBiddingFacade.updateStatusAfterApproval()` |
| 审批拒绝后通知未发送 | `CashbiddingRejectTaskHandler.handleSingle()` → 检查 `NoticeInfoFacade.sendNotice()` 模板编码 |
| OA待办未推送 | `CashBiddingGlobalTaskNoticeHandler.sendOaTodo()` → 检查 `platApproveNode` 列表和 `JinkoOaFlowTypeEnum` |
| 自动委派未生效 | `CashBiddingGlobalTaskNoticeHandler.notice()` → 检查 `AutoDelegateHandler.autoDelegateIfNeed()` |
| 子流程审批人未收到短信 | `CashBiddingGlobalTaskNoticeHandler.notice()` → type=1/2 分支 → `CashBiddingMessageFacade.sendMessageUnclaimPerson()` |
| 节点ID变更 | `CashBiddingWorkFlowConstant` + 流程定义JSON 同步检查 |
| 批量审批异常 | `BiddingFetcher.fetchBidding()` → 检查 `batchNo` 获取逻辑 |
