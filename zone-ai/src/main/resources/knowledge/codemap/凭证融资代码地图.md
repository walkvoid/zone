## 2. 核心数据流

### 2.1 主要业务流程数据流向

```
供应商发起凭证融资申请
  → CashProccessBusinessHandler.doBusiness() [流程启动]
    → CashDataFacade.handleExtData(specialId) 组装流程变量
    → TsAssetFacade.tsAssetTransApply() 冻结凭证可用额度
  → AutoTaskHandler [核心自动节点逻辑分发 - 19个节点]
    → beforeCashOperation: 保存业务相关企业数据
    → needCashAgwAudit: 判断是否需要内管审核 + 资方配置审批前放款
    → signAuditOrder1/2/3: 签审顺序判断（1先签后审/2先审后签/3对接资方需确认/4不需确认）
    → contractSignTypeSpy: 供应商合同签署方式 + 对接各银行(交行/浦发/兴业/浙商/汇丰/招行/大连等)

    → contractSignTypeFinance: 资金方合同签署方式 + 生成资金方合同
    → pay_interest_type: 查询付息方式（债务人/共同/供应商）
    → beforePushToOpssOperation: 推送运营系统审核（推送资产/影像/启动审核流程）
    → loan_success: 正式放款 + 发送转让通知站内信
    → 1676366135377(LOAN_SUCCESS_FUNDS): 对接资金方放款成功
    → 各签署/拒绝签署合同节点
  → CashSpySignContractTaskListenerHandler [供应商签署合同]
  → CashCoreSignContractTaskListenerHandler [核心企业签署合同]
  → CashFinanceSignContractTaskListenerHandler [资金方签署合同]

    → 发送融资转让短信（供应商/共同债务人）
  → CashOpsCheckHandler [运营中台审核]
    → 审核拒绝时作废临时凭证

    → 更新交易状态为拒绝
```

## 3. 工作流执行链路

### 3.1 流程概览

凭证融资主流程包含 **46个节点**，覆盖：融资申请 → 融资审核 → 签审顺序判断 → 供应商/核心企业/资金方三方合同签署 → 付息方式判断 → 放款审核 → 放款成功/失败。

**子流程**：
- 融资审核子流程: MultiTrans-cash_apply_audit
- 直保资产审核子流程: `Flow-6511bc3fb2f04cabb72a14a729e88b27` (MultiTrans-cash_sign_audit)
- 直保放款审核子流程: `Flow-9d716a3b7a7545e9bfbf58f34a82df98` (MultiTrans-cash_loan_audit)

**关键网关条件变量**：
- `autoTaskQueryResult`: 多个自动节点的通用结果变量
- `isOnlineSignFlagSpy/Core`: 供应商/核企合同签署方式（online/offline/nosign/wait）
- `isPayInterestType`: 付息方式（1=核企付息/共同付息, 0=供应商付息）
- `hsbcBankApply`: 是否汇丰/恒生审批（hsbc/hangseng/other）
- `funderLoanResult`: 资金方放款结果

### 3.3 监听器详细说明

#### 3.3.1 CashProccessBusinessHandler（流程启动处理器）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.processbusinesshandler.cash.CashProccessBusinessHandler`
- **绑定**: 流程启动事件（IProcessBusinessHandler）
- **核心逻辑**:
  1. 解析businessData获取specialId（交易ID）
  2. 调用CashDataFacade.handleExtData组装流程变量
  3. 冻结凭证可用额度（tsAssetTransApply）
  4. 设置businessId为specialId
- **依赖服务**: CashDataFacade, TsAssetFacade
- **数据操作**: 冻结凭证可用额度

#### 3.3.2 AutoTaskHandler（核心自动节点处理器 - 最复杂）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.executionlistenerhandler.cash.AutoTaskHandler`
- **绑定节点**: 19个自动节点（contractSignTypeSpy/Core/Finance / pay_interest_type / beforeCashOperation / needCashAgwAudit / splite_tsAsset / loan_success / signAuditOrder1/2/3 / spy_neednot / core_neednot / finance_neednot / reject_spy/core/finance / LOAN_SUCCESS_FUNDS / beforePushToOpssOperation）
- **核心逻辑**:
  - **`contractSignTypeSpy`**: 供应商合同签署方式 + 对接多家银行差异化处理：
    - 交行(bocom): 推送信息给银行，设置wait等待银行回调生成合同
    - 浦发(spd)/兴业(cib)/工行(icbc): 初始化合同信息，走线上签署
    - 浙商(czbankDirect)/招行(cmbc)/大连(bankofdl): 推送信息+初始化合同，走线上签署
    - 汇丰(hsbc): 走线上签署，生成汇丰专用合同
    - 恒生(hangseng): 走线上签署，生成恒生专用合同
    - 渤海(cbhb)/邮储(psbc)/北京(bob)/农行(abc)/广发(cgb): 走线上签署
    - 中信(citic): 走线上签署
    - 默认: 走公用合同生成方法
  - **`contractSignTypeCore`**: 核企合同签署方式 + 生成核企合同
  - **`contractSignTypeFinance`**: 资金方合同签署方式 + 生成资金方合同
  - **`beforeCashOperation`**: 保存在途业务企业数据（saveWkflCust）
  - **`needCashAgwAudit`**: 判断内管审核 + 审批前放款场景调用资金中台
  - **`signAuditOrder1/2/3`**: 签审顺序判断，含复杂的银行差异化逻辑：
    - signAuditOrder3(内管审批后): 工行/招行/邮储/北京/农行/广发提前拆凭证 + 浦发/兴业/招行调银行接口
    - signAuditOrder2(供应商签署后): 判断是否需要资金方确认(浙商=3,其他=4) + 不签合同场景补拆凭证
  - **`pay_interest_type`**: 查询付息方式 + 无需内管审核时占用发票
  - **`beforePushToOpssOperation`**: 推送运营系统审核（推送资产/影像/启动流程/退回补充资料同步）
  - **`loan_success`**: 正式放款 + 发送转让通知站内信
  - **`LOAN_SUCCESS_FUNDS`**: 对接资金方放款成功 + 发送站内信
  - **`reject_sign_contract_spy/core/finance`**: 拒绝签署处理（释放额度/发票/凭证 + 更新交易状态 + 发送通知）
  - **`spy_neednot/core_neednot/finance_neednot`**: 无需签署合同时直接更新签署状态
- **依赖服务**: ProductBusinessProvider, CashDataFacade, ICashProvider, ITransactionProvider, TsAssetFacade, ParamFunderConfigProvider, ApplyFunderLoanProvider, CashStateTaskProvider, TsTransactionProvider, OpssAssetProvider, IBaseContractProvider, NoticeInfoFacade, ParamBusiKeyFacade, ContractInfoFacade, SignContractFacade, ContractSignInfoFacade, IAssetInfoProvider, TsAssetProvider, HolidayInfoProvider, AssetFacade, UserInfoFacade
- **数据操作**: 生成合同、推送银行、拆分凭证、更新交易状态、推送运营系统、占用发票

  6. 判断是否拒绝签署（ifReject）:
     - 是: 发送拒绝签署短信和站内信
     - 否: 更新合同状态为OBSOLETE（已废弃）
  7. 回滚资产数据和影像（rollbackAssetDataAndMedia）
- **依赖服务**: CashDataFacade, ContractInfoProvider, TsAssetBaseProvider, TsTransactionProvider, OpssAssetProvider
- **数据操作**: 释放额度/发票、恢复凭证、更新交易状态、更新合同状态、回滚数据
