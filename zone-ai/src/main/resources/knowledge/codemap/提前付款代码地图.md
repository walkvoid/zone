## 2. 核心数据流

### 2.1 主要业务流程数据流向

```
供应商发起提前付款申请
  → PrepayStartHandler.doBusiness() [流程启动]
    → 查询交易信息 (TsTransactionProvider.getByTransactionId)
    → 查询凭证信息 (TsAssetProvider.getTsAssetDetailById)
    → 查询资产信息 (IAssetInfoProvider.getByAssetNo)
    → 冻结凭证可用额度 (TsAssetFacade.tsAssetTransApply)
    → 同步流程变量（核企/供应商/金额/凭证/申请日期等）
  → PrepayAutoTaskHandler [自动节点逻辑分发]
    → 判断签审顺序 (signAuditFlag: 先签后审/先审后签)
    → 判断是否需要内管审核 (isNeedAgwAudit)
    → 判断供应商合同签署方式 (isOnlineSignFlagSpy)
    → 判断核心企业合同签署方式 (isOnlineSignFlagCore)
    → 生成提前结清确认书
    → 判断支付策略 (payStrategy: 默认/司库)
    → 放款成功处理
  → PrepayAgwAuditTaskListenerHandler [内管审核]
    → 处理内管审核节点任务
  → PrepaySpyAuditTaskListenerHandler [供应商审核]
    → 处理供应商审核节点任务
  → PrepayCoreAuditTaskListenerHandler [核心企业审核]
    → 处理核心企业签收/放款审核
  → PrepaySplitTsAssetExecutionListenerHandler [凭证拆分]
    → 确认服务费 (ITransactionProvider.confirmCashFee)
    → 拆分凭证 (TsAssetFacade.splitTsAsset)
  → PrepayRejectSignContractTaskHandler [拒绝签署处理]
    → 处理合同拒绝签署场景
  → PrepayTerminalBussineessHandler [流程终止]
    → 恢复凭证可用额度
    → 释放发票占用
    → 更新交易状态为拒绝
    → 删除支付记录
```

## 3. 工作流执行链路

### 3.1 流程概览

提前付款主流程包含 **43个节点**，覆盖：融资申请审核 → 签审顺序判断(先签后审/先审后签) → 供应商/核心企业合同签署 → 签收审核 → 放款审核 → 支付(默认/司库)。

**子流程**：
- 提前结清申请审核子流程: MultiTrans-subSpyAudit
- 核心企业签收审核子流程: `Flow-9aa12fa10cfb47048a2cb2708a7f4c40` (MultiTrans-cash_sign_audit)
- 核心企业放款审核子流程: `Flow-9e55785d412f4ee0bc14ec5118049a55` (MultiTrans-cash_loan_audit)

**关键网关条件变量**：
- `signAuditFlag`: 签审顺序（先签后审/先审后签）
- `isNeedAgwAudit`: 是否需要内管审核
- `isOnlineSignFlagSpy`: 供应商合同签署方式（online/offline/nosign）
- `isOnlineSignFlagCore`: 核心企业合同签署方式（online/offline/nosign）
- `payStrategy`: 支付策略（default/siku/司库）
- `formApproveResult`: 审批结果（pass/reject/back）

### 3.3 监听器详细说明

#### 3.3.1 PrepayStartHandler（流程启动处理器）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.processbusinesshandler.prepay.PrepayStartHandler`
- **绑定**: 流程启动事件（IProcessBusinessHandler）
- **核心逻辑**:
  1. 解析businessData获取specialId（交易ID）
  2. 查询TsTransaction交易信息
  3. 查询TsAsset凭证信息
  4. 查询原始资产信息
  5. 冻结凭证可用额度（tsAssetTransApply）
  6. 同步流程扩展变量（ext1~ext19, ext30）:
     - ext1/2: 核心企业ID/名称
     - ext3/4: 凭证开立方ID/名称
     - ext5/6: 融资类型（PREPAY）
     - ext7: 融资申请金额
     - ext8/9: 提前付款申请方ID/名称
     - ext10/11: 凭证ID/编号
     - ext12: 业务ID
     - ext14/15: 资产编号/ID
     - ext18: 司库支付状态（WAIT_COMMIT）
     - ext19: 司库支付结果（默认yes）
- **依赖服务**: TsTransactionProvider, TsAssetProvider, IAssetInfoProvider, TsAssetFacade, UserInfoProvider
- **数据操作**: 冻结凭证可用额度

#### 3.3.2 PrepayAutoTaskHandler（自动节点处理器）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.executionlistenerhandler.prepay.PrepayAutoTaskHandler`
- **绑定节点**: 15个自动节点（needCashSpyAudit / signAuditOrder1&2 / needCashAgwAudit / contractSignTypeSpy&Spy1&Core / decide_pay_strategy / loan_success / spy_offline1&2 / spy_no_need1&2 / core_no_need / core_online_auto_sign）
- **核心逻辑**:
  - `needCashSpyAudit`: 设置formApproveResult=pass（供应商审核自动通过）
  - `signAuditOrder1/2`: 查询签审顺序配置（MULTI_SIGN_AUDIT_FLAG）
  - `needCashAgwAudit`: 查询是否需要内管审核配置（MULTI_IS_NEED_AGW_AUDIT）
  - `contractSignTypeSpy/Spy1`: 转换供应商合同签署方式 + 生成提前结清确认书
  - `contractSignTypeCore`: 转换核心企业合同签署方式
  - `decide_pay_strategy`: 判断支付策略（默认/司库）
  - `loan_success`: 发送放款短信 + 正式放款
  - `spy_offline1/2`: 发送供应商线下签署短信和站内信
  - `spy_no_need1/2`: 供应商无需签署合同处理
  - `core_no_need`: 核心企业无需签署合同处理
  - `core_online_auto_sign`: 核心企业线上自动签署合同
- **依赖服务**: ProductBusinessProvider, PrepayDataFacade, NoticeInfoFacade, CustSettingConfigProvider, TsTransactionProvider
- **数据操作**: 读取配置项、生成合同、发送通知

#### 3.3.3 PrepayAgwAuditTaskListenerHandler（内管审核监听器）

#### 3.3.6 PrepaySplitTsAssetExecutionListenerHandler（凭证拆分）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.executionlistenerhandler.prepay.PrepaySplitTsAssetExecutionListenerHandler`
- **绑定节点**: 6个供应商合同签署/无需签署节点（sign_contract_spy_online1/2, sign_contract_spy_offline1/2, sign_contract_spy_no_need1/2）
- **核心逻辑**:
  1. 仅END事件处理，排除terminate/reject结果
  2. 确认服务费（confirmCashFee，设置供应商签署合同时间）
  3. 拆分凭证（splitTsAsset，按交易金额从母凭证拆分子凭证）
- **依赖服务**: TsAssetFacade, ITransactionProvider
- **数据操作**: 更新服务费确认日期、拆分凭证

- **绑定节点**: 拒绝签署合同相关自动节点
- **核心逻辑**: 处理供应商/核心企业拒绝签署合同后的清理工作

#### 3.3.8 PrepayGlobalTaskNoticeHandler（全局通知处理）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.globaltasknoticehandler.prepay.PrepayGlobalTaskNoticeHandler`
- **绑定**: 全局任务通知事件（IGlobalTaskNoticeHandler）
- **核心逻辑**: 根据taskNoticeType和elementId发送对应的短信和站内信通知

#### 3.3.9 PrepayTerminalBussineessHandler（流程终止处理）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.terminalbusinesshandler.prepay.PrepayTerminalBussineessHandler`
- **绑定**: 流程终止事件（ITerminalBusinessHandler）
- **核心逻辑**:
  1. 判断终止来源（是否为拒绝签署）
  2. 拒绝签署场景：校验签收审核进度 → 更新合同为REJECT → 发送拒绝通知
  3. 恢复凭证可用额度（tsAssetTransFailed）
  4. 释放发票占用（realseInvoice）
  5. 更新交易状态为REJECT
  6. 删除支付记录（removeByTsAssetNo）
- **依赖服务**: TsTransactionProvider, TsAssetBaseProvider, ContractInfoProvider, ContractSignInfoProvider, IContractBusinessProvider, PrepayDataFacade, PayTradeProvider
- **数据操作**: 更新合同状态、恢复凭证额度、释放发票、更新交易状态、删除支付记录

| 合同签署方式错误 | PrepayAutoTaskHandler → contractSignTypeSpy → PrepayDataFacade.convertSignMode() |

| 放款失败 | PrepayAutoTaskHandler → loan_success → PrepayDataFacade.prepayLoanPass() |
| 支付策略错误 | PrepayAutoTaskHandler → decide_pay_strategy → PrepayDataFacade.decidePayStrategy() |
