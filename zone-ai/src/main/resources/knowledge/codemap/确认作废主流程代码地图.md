## 2. 核心数据流

### 2.1 主要业务流程数据流向

```
凭证作废申请提交
  → 启动流程（AbolishStartHandler）
    → 数据初始化自动节点（AbolishAutoTaskHandler: AUTOTASK_FLOW_START）
    → 供应链财务BP审核（人工审批 RushSignTask-fin_bp_audit）
      ├─ pass → 财务BP通过自动节点（AUTOTASK_FIN_BP_AUDIT_PASS）
      │         → 资金管理部审核（人工审批 RushSignTask-fin_manage_audit）
      │           ├─ pass → 资金管理部通过自动节点（AUTOTASK_FIN_MANAGE_AUDIT_PASS）→ 作废成功
      │           ├─ reject → 审核拒绝自动节点（AUTOTASK_AUDIT_REJECT）→ 作废失败
      │           └─ back → 退回
      ├─ reject → 审核拒绝自动节点（AUTOTASK_AUDIT_REJECT）→ 作废失败
      └─ back → 退回
```

### 2.2 跨模块调用链路

```
[jinkoscf-workflow]                         [jinkoscf-transaction / jinkoscf-business-common]
  AbolishStartHandler
    ├─ TsAssetFacade.getTsAssetDetailById() ─→ TsAssetProvider(Dubbo)
    ├─ TsAssetFacade.getByAssetNo()  ────────→ AcflowAssetInfoProvider
    └─ TsAssetAbolishApplyProvider.getById() → TsAssetAbolishApplyProvider(Dubbo)
  AbolishAutoTaskHandler
    ├─ AbolishFacade.abolishSuccess()  ──────→ 作废成功业务处理
    └─ AbolishFacade.abolishFail()  ─────────→ 作废失败业务处理
  AbolishGlobalTaskNoticeHandler
    └─ AbolishFacade.sendAbolishOATodo()  ──→ OA待办通知
  AbolishApprpveClientProvider
    └─ 从流程变量获取 client（审批人企业标识）
```

## 3. 工作流执行链路

### 3.1 流程概览

| 属性 | 值 |
|------|---|
| 流程 Key | `Flow-fa7f1c36b2b94aa79528f47f8de64b40` |
| 流程名称 | 确认作废主流程 |
| 节点数量 | 10 个 |
| 流程定义文件 | `jinkoscf-common/.dev-standards/knowledge/procdefs/确认作废主流程-V86.json` |

### 3.2 关键节点与监听器

| 节点 ID | 节点名称 | 监听器类 | 事件类型 | 核心逻辑 |
|---------|---------|---------|---------|---------|
| (全局) | 流程启动 | AbolishStartHandler | ProcessBusiness | 解析tsAssetId/businessId，初始化流程变量（tsAssetNo, assetNo, sellerName, assetAmount, expireDate等） |
| (全局) | 全局任务通知 | AbolishGlobalTaskNoticeHandler | GlobalTaskNotice | 调用 AbolishFacade 发送OA待办通知 |
| AutoTask-flow_start | 流程开始自动节点 | AbolishAutoTaskHandler | ExecutionListener(END) | 空处理（break） |
| RushSignTask-fin_bp_audit | 供应链财务BP审核 | AbolishApprpveClientProvider | TaskApproveClient | 从流程变量中获取 client 设置审批人 |
| AutoTask-fin_bp_audit_pass | 财务BP通过 | AbolishAutoTaskHandler | ExecutionListener(END) | 空处理（break） |
| RushSignTask-fin_manage_audit | 资金管理部审核 | AbolishApprpveClientProvider | TaskApproveClient | 从流程变量中获取 client 设置审批人 |
| AutoTask-fin_manage_audit_pass | 最终审批通过 | AbolishAutoTaskHandler | ExecutionListener(END) | 调用 `abolishFacade.abolishSuccess()` 执行作废成功逻辑 |
| AutoTask-audit_reject | 审核拒绝 | AbolishAutoTaskHandler | ExecutionListener(END) | 调用 `abolishFacade.abolishFail()` 执行作废失败逻辑 |

### 3.3 监听器详细说明

#### 3.3.1 AbolishStartHandler（流程启动拓展器）

| 属性 | 值 |
|------|---|
| 完整类名 | `com.lls.cloud.scf.workflow.provider.exthandler.listener.processbusinesshandler.abolish.AbolishStartHandler` |
| 文件路径 | `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/processbusinesshandler/abolish/AbolishStartHandler.java` |
| 实现接口 | `IProcessBusinessHandler` |
| 绑定节点 | 全局（流程启动时触发） |
| 核心逻辑 | 1. 从 businessData JSON 中解析 tsAssetId 和 businessId；2. 查询凭证信息（TsAssetDTO）和资产信息（AcflowAssetInfoDTO）；3. 查询作废申请（TsAssetAbolishApplyDTO）；4. 设置流程变量：tsAssetNo, sellerName, assetNo, assetAmount, expireDate, abolishApplyDate, tsAssetId, assetId, coreCompanyName, confirmCompanyId, shareDeptName, fundsName, buyerName |
| 依赖服务 | TsAssetFacade, TsAssetAbolishApplyProvider(Dubbo) |

#### 3.3.2 AbolishGlobalTaskNoticeHandler（全局任务通知）

| 属性 | 值 |
|------|---|
| 完整类名 | `com.lls.cloud.scf.workflow.provider.exthandler.listener.globaltasknoticehandler.abolish.AbolishGlobalTaskNoticeHandler` |
| 文件路径 | `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/globaltasknoticehandler/abolish/AbolishGlobalTaskNoticeHandler.java` |
| 实现接口 | `IGlobalTaskNoticeHandler` |

| 依赖服务 | AbolishFacade |

#### 3.3.3 AbolishAutoTaskHandler（自动节点处理）

| 属性 | 值 |
|------|---|
| 完整类名 | `com.lls.cloud.scf.workflow.provider.exthandler.listener.executionlistenerhandler.abolish.AbolishAutoTaskHandler` |
| 文件路径 | `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/executionlistenerhandler/abolish/AbolishAutoTaskHandler.java` |
| 实现接口 | `IExecutionListenerHandler` |
| 绑定节点 | AutoTask-flow_start, AutoTask-fin_bp_audit_pass, AutoTask-fin_manage_audit_pass, AutoTask-audit_reject |

## 5. 修改热点区域

| 热点文件 | 修改频率 | 说明 |
|---------|---------|------|
| AbolishAutoTaskHandler.java | 高 | 自动节点处理逻辑，作废成功/失败的业务处理入口 |
| AbolishFacade.java | 高 | 封装作废成功/失败/OA通知的具体业务逻辑 |
| AbolishStartHandler.java | 中 | 流程启动变量初始化 |
| AbolishWorkFlowConstant.java | 低 | 节点 ID 常量（已有大量 @Deprecated 旧节点） |
| AbolishGlobalTaskNoticeHandler.java | 低 | OA待办通知 |

**注意**: `AbolishAutoTaskHandler1.java`（带后缀1）存在于同目录，可能是旧版本备份，需确认是否清理。

## 6. 快速定位指南

| 需求 | 定位路径 |
|------|---------|
| 流程启动时初始化了哪些变量 | `AbolishStartHandler.doBusiness()` |
| 作废成功后做了什么 | `AbolishAutoTaskHandler` → `AUTOTASK_FIN_MANAGE_AUDIT_PASS` → `abolishFacade.abolishSuccess()` |
| 作废失败后做了什么 | `AbolishAutoTaskHandler` → `AUTOTASK_AUDIT_REJECT` → `abolishFacade.abolishFail()` |
| 审批人如何确定 | `AbolishApprpveClientProvider.fillTaskApproveClient()` → 从流程变量 VAR_CLIENT 获取 |
| OA待办如何发送 | `AbolishGlobalTaskNoticeHandler.notice()` → `abolishFacade.sendAbolishOATodo()` |
| 节点 ID 常量定义 | `AbolishWorkFlowConstant` 接口（注意新旧版本节点区分） |
| 流程定义 JSON | `jinkoscf-common/.dev-standards/knowledge/procdefs/确认作废主流程-V86.json` |
| 旧版已废弃节点 | `AbolishWorkFlowConstant` 中带 `@Deprecated` 注解的常量 |
