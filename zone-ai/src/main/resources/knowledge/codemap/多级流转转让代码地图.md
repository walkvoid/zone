# 多级流转转让主流程代码地图

> 本文档描述「多级流转转让」工作流的代码结构、核心数据流与监听器链路，帮助开发者快速定位和理解凭证转让相关代码。
> 流程Key: `Flow-3072c98e8486455aa2a391a4d6cdd299`（常量 `TransferWorkFlowConstant.TRANSFER_MAIN_FLOW`）
> 复杂度：高（40节点，含2个子流程、线上/线下/免签三种签署模式、多种拒绝路径）

## 3. 工作流执行链路

### 3.1 流程概览（40节点主链路）

```
启动(TransferStartHandler)
  │ 设置signMode、formApproveResult=pass、调用tsAssetTransferApply
  │
  ▼
检查底层资料(CheckMaterialExecutionListenerHandler)
  │ AutoTask-check_material（安全性验证）
  │
  ▼
上传贸易背景资料(SupplementMaterialTaskListenerHandler)
  │ RushSignTask-supplement_material（人工节点，可退回补充）
  │ 创建时保存贸易背景快照
  │
  ▼
转让方审批子流程(MultiTrans-1662381986477)
  │ LAUCH_SUB_PROCESS_NODE
  │ 子流程结果: pass → 继续 / reject → 拒绝处理 / back → 退回补充资料
  │
  ▼
转让方合同签署判断(AutoTask-sign_mode_from_launch)
  │
  ├── signMode=01(线上) ──→ 转让方合同签署自动任务(SignByLaunchExecutionListenerHandler)
  │                          │ 调用sedContractSign生成合同
  │                          │ 复制影像到流水影像树
  │                          │ 关闭合同签署状态(APPROVAL)
  │                          ▼
  │                        转让方线上签署(RushSignTask-launch_online_sign)
  │
  ├── signMode=02(线下) ──→ 转让方合同签署自动任务(SignByLaunchExecutionListenerHandler)
  │                          ▼
  │                        转让方线下签署(RushSignTask-launch_offline_sign)
  │
  └── signMode=03(免签) ──→ 转让方合同签署自动任务(SignByLaunchExecutionListenerHandler)
                             │ 更新签署类型为TO_BE_SIGNED
                             │ 调用updateContractSignStatus
                             ▼
                           直接进入运营中台审核
  │
  ▼
运营中台审核（内管审批节点）
  │
  ▼
等待签收(RushSignTask-wait_sign_in)
  │ 发送等待签收短信/通知给签收方
  │ 签收方可以: pass(签收) / reject(拒绝签收)
  │
  ▼
签收方审批子流程(MultiTrans-1662382165855)
  │ RECEIVE_SUB_PROCESS_NODE
  │ 子流程结果: pass → 继续 / reject → 拒绝通知转让方
  │
  ▼
签收方合同签署判断(AutoTask-sign_mode_from_receiver)
  │
  ├── signMode=01(线上) ──→ 签收方线上签署(RushSignTask-receiver_online_sign)
  │
  └── signMode=02(线下) ──→ 签收方线下签署(RushSignTask-receiver_offline_sign)
  │
  ▼
签收方合同签署自动任务(SignByReceiverExecutionListenerHandler)
  │ 调用transferSignIn完成签收
  │ 发送资产转让通知站内信给核心企业
  │
  ▼
凭证拆分(TransferSplitTsAssetExecutionListenerHandler)
  │ 调用transferSplitTsAssetAndCreatePdf拆分凭证并生成PDF
  │
  ▼
流程结束(End-1662034967252)
  │ 发送转让通知书给核心企业（站内信+短信）
```

### 3.2 拒绝路径汇总（7种拒绝节点）

```
拒绝节点统一处理: TransferRejectListenerHandler

┌─────────────────────────────────────────────────────────────────────┐
│ 拒绝节点                          │ 处理方式                       │
├─────────────────────────────────────────────────────────────────────┤
│ AutoTask-lauch_subprocess_reject  │ dealTransferReject(lotId,false)│
│ AutoTask-reciver_reject_sign_in   │ dealTransferReject(lotId,false)│
│ AutoTask-receiver_subprocess_reject│dealTransferReject(lotId,false)│
│ AutoTask-lauch_online_sign_reject │ dealTransferReject(lotId,true) │
│ AutoTask-lauch_offline_sign_reject│ dealTransferReject(lotId,true) │
│ AutoTask-receiver_online_sign_reject│dealTransferReject(lotId,true)│
│ AutoTask-receiver_offline_sign_reject│dealTransferReject(lotId,true│
└─────────────────────────────────────────────────────────────────────┘

说明: 
- false = 仅回退交易状态（子流程拒绝、拒绝签收 → 可重新发起）
- true  = 终止交易并回退（合同签署拒绝 → 不可恢复）

流程终结: TransferTerminalBussineessHandler
- 调用dealTransferReject(lotId, true)终止交易
- 发送拒绝通知（站内信+短信）给转让方发起人
```

### 3.3 监听器详细说明

#### 3.3.1 TransferStartHandler（流程启动扩展器）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/processbusinesshandler/transfer/TransferStartHandler.java`

**接口**: `IProcessBusinessHandler`

**核心逻辑**:
1. 从 `businessData` JSON中解析 `specialId`（作为真正的businessId/appNo）和 `signMode`
2. 调用 `TsAssetFacade.tsAssetTransferApply()` 触发凭证资产转让申请
3. 设置流程变量: `formApproveResult=pass`、`signMode`、`transferAmount`
4. 返回 `appNo` 作为流程业务ID

**RPC依赖**: `ProductBusinessProvider`、`WorkflowNewProvider`、`TsTransactionLotProvider`、`TsAssetFacade`

---

#### 3.3.2 TransferGlobalTaskNoticeHandler（全局任务通知 — 最复杂，1081行）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/globaltasknoticehandler/transfer/TransferGlobalTaskNoticeHandler.java`

**接口**: `IGlobalTaskNoticeHandler`

**核心逻辑 — 按taskNoticeType分支**:

##### taskNoticeType=1（待抢通知）

| 节点 | 处理 |
|------|------|
| 发起方子流程节点 | 发送内审提醒短信(`TRANSFER_LAUCH_INNER_AUDIE_REMIND`) |
| 签收方子流程节点 | 发送内审提醒短信(`TRANSFER_REC_INNER_AUDIE_REMIND`) |
| 等待签收节点 | 发送等待签收短信 + 线下模式额外发送合同签署短信 |
| 发起方线上签署节点 | 发送合同签署短信 + 站内信通知 |
| 签收方线上/线下签署节点 | 发送合同签署短信 |

##### taskNoticeType=2（待办通知）
- 与type=1类似，但增加 `autoClaimFlag` 判断（自动领取时才发送）

##### taskNoticeType=3（流程结束通知）
- **子流程结束**:
  - 发起方子流程拒绝 → 通知转让方发起人 + 短信
  - 发起方子流程通过 → 通知转让方审批通过
  - 发起方子流程退回 → 通知并自动领取补充资料任务
  - 签收方子流程拒绝 → 通知转让方发起人
- **主流程结束(pass)** → 遍历交易明细，向每笔凭证的核心企业发送转让通知书（站内信+短信）

##### taskNoticeType=4（任务办理完成）
- 签收方拒绝签收 → 通知转让方 + 短信
- 签收方签收成功 → 发送签收成功通知
- 发起方拒绝合同签署 → 通知 + 短信

**RPC依赖**: `TsTransactionLotProvider`、`TsTransactionProvider`、`TsAssetProvider`、`ITransferTransactionProvider`、`UserInfoFacade`、`NoticeInfoFacade`、`MessageInfoFacade`、`WorkflowNewProvider`、`FlowCustCompanyInfoProvider`、`PpbPortalProvider`

---

#### 3.3.3 CheckMaterialExecutionListenerHandler（底层资料检查）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/executionlistenerhandler/transfer/CheckMaterialExecutionListenerHandler.java`

**接口**: `IExecutionListenerHandler`

**核心逻辑**: 当前为透传节点（历史代码已注释），仅记录日志。原设计用于判断是否需要上传底层资料和转让方/签收方审批。

#### 3.3.4 SupplementMaterialTaskListenerHandler（补充贸易背景资料）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/tasklistenerhandler/transfer/SupplementMaterialTaskListenerHandler.java`

**接口**: `ITaskListenerHandler`

**核心逻辑**:
1. `CREATE` 事件：调用 `IGenericSnapshotRecordProvider.recordBusinessSnapshot()` 保存贸易背景快照（用于审计追溯）
2. `COMPLETE` 事件：审批通过时透传流程变量

**RPC依赖**: `IGenericSnapshotRecordProvider`、`UserInfoFacade`

---

#### 3.3.5 SignByLaunchExecutionListenerHandler（转让方合同签署）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/executionlistenerhandler/transfer/SignByLaunchExecutionListenerHandler.java`

**接口**: `IExecutionListenerHandler`

**核心逻辑（START事件）**:

| signMode | 处理 |
|----------|------|
| `01`(线上) | 调用 `sedContractSign()` 生成签署合同 → 复制影像到流水影像树 → 关闭合同签署状态(`APPROVAL`) |
| `02`(线下) | 不生成合同，走线下手动签署流程 |
| `03`(免签) | 获取合同模板签署ID → 批量更新签署类型为 `TO_BE_SIGNED` → 调用 `updateContractSignStatus` |

**通用处理**: 设置 `noticeCustName=签收方企业名` 用于后续站内信通知

**RPC依赖**: `ITransferSignProvider`、`ITransferTransactionProvider`、`IDocMediaProvider`、`ContractInfoProvider`、`TsTransactionProvider`、`TsTransactionLotProvider`、`IMediaOperaProvider`、`SignContractFacade`、`ParamBusiKeyFacade`、`ContractInfoFacade`、`ContractSignInfoFacade`

---

#### 3.3.6 TransferSplitTsAssetExecutionListenerHandler（凭证拆分）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/executionlistenerhandler/transfer/TransferSplitTsAssetExecutionListenerHandler.java`

**接口**: `IExecutionListenerHandler`

**核心逻辑（END事件）**: 调用 `TsAssetFacade.transferSplitTsAssetAndCreatePdf(lotId, userId)` 执行凭证拆分并生成PDF文件

**RPC依赖**: `TsAssetFacade`

#### 3.3.7 SignByReceiverExecutionListenerHandler（签收方合同签署）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/executionlistenerhandler/transfer/SignByReceiverExecutionListenerHandler.java`

**接口**: `IExecutionListenerHandler`

**核心逻辑（START事件）**:
1. 调用 `ITransferTransactionProvider.transferSignIn(lotId, userCode)` 完成签收
2. 遍历交易明细，为每笔凭证的核心企业发送资产转让通知站内信(`ASSET_TRANSFER_NOTICE`)
3. 通知接收人包括核心企业授权用户 + 资产创建人

**RPC依赖**: `ITransferTransactionProvider`、`TsTransactionProvider`、`TsAssetProvider`、`FlowCustCompanyInfoProvider`、`UserInfoFacade`、`NoticeInfoFacade`

---

#### 3.3.8 TransferRejectListenerHandler（统一拒绝处理）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/executionlistenerhandler/transfer/TransferRejectListenerHandler.java`

**接口**: `IExecutionListenerHandler`

**核心逻辑（END事件）**: 根据节点Key调用 `dealTransferReject(lotId, isTerminate)`

| 节点 | isTerminate | 说明 |
|------|-------------|------|
| 发起方子流程拒绝 | `false` | 回退交易状态，可重新发起 |
| 签收方拒绝签收 | `false` | 回退交易状态 |
| 签收方子流程拒绝 | `false` | 回退交易状态 |
| 发起方线上签署拒绝 | `true` | 终止交易并回退 |
| 发起方线下签署拒绝 | `true` | 终止交易并回退 |
| 签收方线上签署拒绝 | `true` | 终止交易并回退 |
| 签收方线下签署拒绝 | `true` | 终止交易并回退 |

**RPC依赖**: `ITransferTransactionProvider`

---

#### 3.3.9 TransferTerminalBussineessHandler（流程终结处理）

**文件路径**: `jinkoscf-workflow/jinkoscf-workflow-provider/src/main/java/com/lls/cloud/scf/workflow/provider/exthandler/listener/terminalbusinesshandler/transfer/TransferTerminalBussineessHandler.java`

**接口**: `ITerminalBusinessHandler`

**核心逻辑**:

2. 发送拒绝签署合同站内信通知给转让方发起人
3. 发送拒绝签署合同短信给发起人

**RPC依赖**: `ITransferTransactionProvider`、`TsTransactionLotProvider`、`NoticeInfoFacade`、`MessageInfoFacade`、`UserInfoFacade`

## 6. 快速定位指南

| 场景 | 定位文件 |
|------|----------|
