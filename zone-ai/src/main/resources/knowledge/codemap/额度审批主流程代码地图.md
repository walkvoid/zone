## 2. 核心数据流

### 2.1 主要业务流程数据流向

```
额度申请提交
  → 启动流程（LimitApplyProccessBusinessHandler）
    → 初始化额度数据 + 核查（AutoInitializeLimitTaskHandler）
      → 根据 applyType 分流:
        ├─ NEW（额度新增）  → 新增初审 → 新增复核
        ├─ UPDATE（额度变更）→ 变更初审 → 变更复核
        └─ ALLOT（额度分配）→ 分配初审 → 分配复核
      → 初审提交处理（LimitFirstApproveTaskListenerHandler）
        ├─ pass → 复核节点
        └─ reject → 拒绝处理（LimitApplyFailTaskHandler）
      → 复核通过 → 成功处理（LimitApplySucessTaskHandler）
      → 复核拒绝 → 拒绝处理（LimitApplyFailTaskHandler）
```

### 2.2 跨模块调用链路

```
[jinkoscf-workflow]                         [jinkoscf-business-common]
  LimitApplyProccessBusinessHandler
    └─ LimitApplyFacade.getById()  ─────→  ApplyLimitInfoOuterProvider(RPC/Dubbo)
  AutoInitializeLimitTaskHandler
    ├─ LimitApplyFacade.getById()  ─────→  ApplyLimitInfoOuterProvider
    ├─ LimitFacade.queryLimtInfo() ─────→  LimitInfoOuterProvider
    ├─ LimitFacade.doOccupateCreditLimit() → LimitOperateProvider
    ├─ LimitFacade.freezeLimitInfo()  ──→  LimitOperateProvider
    └─ BusinessLimitAutocheckVerifyOuterProvider (核查)
  LimitFirstApproveTaskListenerHandler
    ├─ LimitApplyFacade.getById()
    ├─ LimitFacade.queryLimtInfo()
    ├─ LimitFacade.doOccupateCreditLimit()
    ├─ LimitFacade.doCancelCreditLimit()
    └─ LimitFacade.freezeLimitInfo() / doUnfreezeCreditLimit()
  LimitApplyFailTaskHandler
    ├─ LimitApplyFacade.updateLimitApplyStatus() → 更新状态为REJECTED
    ├─ LimitFacade.doCancelCreditLimit()
    ├─ LimitFacade.doUnfreezeCreditLimit()
    ├─ UserInfoFacade.getByIdDto()  ────→  UserInfoOuterProvider
    └─ NoticeInfoFacade.sendNotice()  ──→  NoticeProvider
  LimitApplySucessTaskHandler
    ├─ LimitApplyFacade.updateLimitApplyStatus() → 更新状态为PASSED
    ├─ LimitFacade.doApplyCreditLmt()  → 新增/分配/变更额度
    ├─ LimitFacade.doUnfreezeCreditLimit()
    ├─ UserInfoFacade (发起人、核心企业授权人、资金方授权人)
    └─ NoticeInfoFacade.sendNotice()
```

| RushSignTask-1663840707464 | 调整额度风控初审 | LimitFirstApproveTaskListenerHandler | TaskListener(COMPLETE) | 同上，额度变更还涉及解冻/重新冻结 |
| RushSignTask-1663846133135 | 分配额度风控初审 | LimitFirstApproveTaskListenerHandler | TaskListener(COMPLETE) | 同上，额度分配涉及占用父额度 |
| RushSignTask-1663555536025 | 新增额度风控复核 | - | 人工审批 | 复核节点 |
| RushSignTask-1663840935703 | 调整额度风控复核 | - | 人工审批 | 复核节点 |
| RushSignTask-1663846228369 | 分配额度风控复核 | - | 人工审批 | 复核节点 |
| AutoTask-1663840928249 | 审批拒绝 | LimitApplyFailTaskHandler | ExecutionListener(END) | 取消占用、解冻、更新状态为REJECTED、发送拒绝站内信 |

| 依赖服务 | LimitApplyFacade → ApplyLimitInfoOuterProvider(Dubbo) |

#### 3.3.3 AutoInitializeLimitTaskHandler（初始化额度处理）

| 属性 | 值 |
|------|---|

| 实现接口 | `ITaskListenerHandler` |

## 6. 快速定位指南

| 需求 | 定位路径 |
|------|---------|
| 流程启动时初始化了哪些变量 | `LimitApplyProccessBusinessHandler.syncWkflExtData()` |
| 额度申请类型如何分流 | `AutoInitializeLimitTaskHandler.notice()` → 设置 `formApproveResult` = applyType.dictParam |
| 初审通过后做了什么 | `LimitFirstApproveTaskListenerHandler.notice()` → COMPLETE + PASS 分支 |
| 审批拒绝后额度如何恢复 | `LimitApplyFailTaskHandler.notice()` → doUnfreezeCreditLimit + doCancelCreditLimit |
| 审批通过后额度如何生效 | `LimitApplySucessTaskHandler.notice()` → doApplyCreditLmt |
| 站内信发送规则 | 通过: LIMIT_03(发起人), LIMIT_06(核心企业), LIMIT_07(资金方)；拒绝: LIMIT_04(发起人) |
| 节点 ID 常量定义 | `LimitWorkFlowConstant` 接口 |
| 流程定义 JSON | `jinkoscf-common/.dev-standards/knowledge/procdefs/额度审批主流程-V4.json` |
