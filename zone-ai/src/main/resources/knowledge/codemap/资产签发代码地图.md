## 2. 核心数据流

### 2.1 主要业务流程数据流向

```
用户发起凭证开立申请
  → IssueStartHandler.doBusiness() [流程启动]
    → 获取资产信息 (IAssetInfoProvider.getAssetByIdOrNo)
    → 获取签署配置 (ProductBusinessProvider.getAssetSignConfig)
    → 占用额度 (CustomLimitProvider.holdBillLimit)
    → 同步流程变量 (syncWkflExtData: specialId/assetNo/coreCompany/supplierCompany等)
  → IssueCommonExecutionHandler [自动节点逻辑分发]
    → 判断是否上传底层资料 (needUpload)
    → 判断上传节点 (uploadNode: issue/transaction)
    → 判断上传方 (judgeUploader: core/supplier/agw/all)
    → 判断是否需要审核 (dataAudited)
    → 推送运营系统 (AcfolwAssetOpsService.pushAndStart)
  → IssueOpsAuditExecutionHandler [运营审核回调]
    → 接收运营中台审核结果
  → IssueAuthRightTaskListenerHandler [确权审核]
    → 发送确权通知短信
  → IssueCreateTsAssetExecutionHandler [生成凭证]
    → 更新确权日期
    → 创建TsAsset凭证记录 (TsAssetProvider.createTsAsset)
    → 生成凭证编号 (BusinessNoProvider.getBusinessNo)
    → 补充凭证扩展信息 (TsAssetFacade.createTsAssetExt)
  → IssueTsAssetSignExecutionHandler [凭证签收]
    → 更新凭证状态为已签收
    → 更新资产状态为已签收
  → IssueTerminalBussineessHandler [流程终止]
    → 删除付款确认文件
    → 释放额度 (CustomLimitProvider.releaseBillLimit)
    → 删除临时凭证
```

## 3. 工作流执行链路

### 3.1 流程概览

凭证签发主流程包含 **53个节点**，覆盖：底层资料上传 → 资料审核 → 确权审核(auto/manual, single/double) → 合同签署(online/offline/nosign) → 生成数字债权凭证 → 签收确认 → 签收审核。

**子流程**：
- 确权审核子流程: `Flow-19463e2edffc4308b48e5d9edc13ef24` (MultiTrans-confirm_audit)
- 开单签收审核子流程: (MultiTrans-sign_audit)

**关键网关条件变量**：
- `needUpload`: 是否需要上传底层资料
- `uploadNode`: 上传节点（issue/transaction）
- `judgeUploader`: 上传方（core/supplier/agw/all）
- `dataAudited`: 是否需要审核（yes/no）
- `confirmAuditType`: 确权审核方式（auto/manual）
- `confirmMode`: 确权模式（single/double）
- `voucherIssueSignMode`: 合同签署方式（01线上/02线下/03无需签署）
- `autoReceive`: 是否自动签收
- `signAudit`: 是否需要签收审核

### 3.3 监听器详细说明

#### 3.3.1 IssueStartHandler（流程启动处理器）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.processbusinesshandler.issue.IssueStartHandler`
- **绑定**: 流程启动事件（IProcessBusinessHandler）
- **核心逻辑**:
  1. 解析businessData获取specialId（资产ID）
  2. 查询原始资产信息和签署配置
  3. 获取产品参数（签署方式、共同债务人配置等）
  4. 保存签署配置到资产扩展字段
  5. 生成雪花ID作为businessId
  6. 同步流程扩展变量（specialId/assetNo/coreCompany/supplierCompany等18个变量）
  7. 占用核企/共同债务人额度
- **依赖服务**: IAssetInfoProvider, ProductBusinessProvider, CustomLimitProvider, FlowCustCompanyInfoProvider
- **数据操作**: 更新资产扩展字段(assetSignSetting/assetSignTradeSetting)、占用额度

#### 3.3.2 IssueCommonExecutionHandler（通用自动节点处理）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.executionlistenerhandler.issue.IssueCommonExecutionHandler`
- **绑定节点**: 14个自动节点（whether_bill_upload / bill_upload_node / upload_status / judge_uploader / data_audited / zhongdeng_query / zhongdeng_node / sign_mode / sign_mode2 / sign_audit / auto_receive / confirm_audit_type / business_source / 1683276320993）
- **核心逻辑**:
  - `whether_bill_upload`: 查询是否需要上传底层资料，更新资产状态为INIT
  - `bill_upload_node`: 判断上传节点（基于businessSource）
  - `upload_status`: 判断底层资料是否已上传，更新资产状态
  - `judge_uploader`: 判断上传方（core/supplier/agw/all），区分退回补充材料场景
  - `data_audited`: 判断是否需要审核，推送运营系统或直接进入确权
  - `sign_mode`: 获取合同签署方式，更新资产状态为确权中
  - `auto_receive`: 判断自动/手动签收，更新凭证和资产状态
  - `confirm_audit_type`: 判断确权审核方式（auto/manual）
  - `business_source`: 更新底层资产审核状态
- **依赖服务**: IAssetInfoProvider, ParamBusiKeyFacade, AcfolwAssetOpsService, ITransferProvider, IMediaOperaProvider, CustomLimitProvider, TsAssetProvider, OpssAssetProvider
- **数据操作**: 更新资产状态、推送运营中台、更新凭证状态、更新扩展字段

#### 3.3.3 IssueCreateTsAssetExecutionHandler（生成凭证）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.executionlistenerhandler.issue.IssueCreateTsAssetExecutionHandler`
- **绑定节点**: AutoTask-create_ts_asset
- **核心逻辑**:
  1. START事件：更新确权日期
  2. END事件：删除旧凭证 → 创建新TsAsset记录 → 生成凭证编号 → 补充扩展信息 → 回写凭证开立时间 → 更新资产状态为签收中
- **依赖服务**: AssetProvider, TsAssetProvider, BusinessNoProvider, CustCompanyInfoOuterProvider, CustAccountInfoOuterProvider, TsAssetFacade
- **数据操作**: 创建ts_asset记录、更新ts_asset_ext、更新资产状态

#### 3.3.4 IssueGlobalTaskNoticeHandler（全局通知处理）

- **完整类名**: `com.lls.cloud.scf.workflow.provider.exthandler.listener.globaltasknoticehandler.issue.IssueGlobalTaskNoticeHandler`
- **绑定**: 全局任务通知事件（IGlobalTaskNoticeHandler）
- **核心逻辑**:
  - taskNoticeType=1（待抢通知）: 根据节点类型发送核企合同签署短信、供应商签收短信
  - taskNoticeType=2（待办通知）: 自动领取时发送合同签署/签收短信和站内信
  - taskNoticeType=4（办理完成）: 发送退回/拒绝短信
  - taskNoticeType=5（子流程结束）: 根据父流程节点发送核企/供应商站内信
  - taskNoticeType=6（终止流程）: 发送撤销/拒绝签署通知
- **依赖服务**: NoticeInfoFacade, UserInfoFacade, MessageInfoFacade, FlowCustCompanyInfoProvider, CustCompanyInfoOuterProvider, UserCustRoleRelProvider, TsAssetProvider, NoticeProvider, MessageSmsLogProvider
- **数据操作**: 发送短信、站内信

## 6. 快速定位指南

| 场景 | 定位路径 |
|------|---------|
| 流程启动失败 | IssueStartHandler.doBusiness() → 检查specialId/businessData |
| 底层资料上传不显示 | IssueCommonExecutionHandler → judge_uploader节点 → ParamBusiKeyFacade.getJudgeUploader() |
| 审核推送运营失败 | IssueCommonExecutionHandler → data_audited节点 → AcfolwAssetOpsService.pushAndStart() |
| 确权方式判断错误 | IssueCommonExecutionHandler → confirm_audit_type节点 → ParamBusiKeyFacade.getConfirmAuditType() |
| 合同签署方式错误 | IssueCommonExecutionHandler → sign_mode节点 → ParamBusiKeyFacade.getVoucherIssueSignMode() |
| 凭证生成失败 | IssueCreateTsAssetExecutionHandler.notice() → createTsAsset() |
| 签收状态异常 | IssueCommonExecutionHandler → auto_receive节点 / IssueTsAssetSignExecutionHandler |
| 额度占用/释放异常 | IssueStartHandler(占用) / IssueTerminalBussineessHandler(释放) → CustomLimitProvider |
| 通知短信未发送 | IssueGlobalTaskNoticeHandler.notice() → 根据taskNoticeType和elementId定位分支 |
| 流程终止异常 | IssueTerminalBussineessHandler.doTerminal() → 检查额度释放和凭证删除 |
